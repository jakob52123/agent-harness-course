前面看完了四家 Harness 底座，从这一页开始，我们转来看用底座搭出来的 Agent 产品。我们怎么看待 AI，决定了给它搭什么样的 Harness。这四级台阶不是死板的硬分类，而是帮大家看懂市面上常见 Agent 产品形态的一把尺子。

第一级「工具」，就是普通聊天框，一问一答，没有 Loop，不会自己动手。第二级「协作者」，给模型套上了完整的 Harness 和 Loop，默认等你下指令，它自己把一圈圈循环跑完。

第三级「同事」，在 Harness 外面多配了事件触发和独立工作区——有的是每单独立会话和工作目录，有的是直接配一台云电脑，不用人盯着，来活就能自己接、后台接着干。第四级「组织」，再加一层总管路由和多会话调度，分拣派单，多个 Agent 并行干活。

再往上看第三级「同事」。DeepSeek 发过一篇 Super-agent 设计文章，也开源了一个研究原型。官方明说这只是研究原型，不是正式产品，和内部版本、和文章里的完整设计也不完全一样。

它要解决什么问题？按他们团队自己的经验，几个任务并行跑的时候，人得手动切窗口，通常同时只能跟进 3 到 5 个活跃会话。所以它的设计原则就一句：尽量少占人的注意力。

顺着屏幕四站看：第一站进消息，文章写接 IM 和 GitHub，公开原型支持 GitHub 和可选的飞书，飞书默认是关的。第二站 Router（原型里叫主 Session），负责接单分拣。第三站 Worker（原型里叫执行器 Session），图上画 3 个只是示意，不是固定数量，实际是每张工单开一个独立会话和工作目录去干。第四站干完报就绪，直接回到原来的对话里交差。

想要一个像同事一样的个人 Agent，就得给它配齐屏幕上这三样：自己的电脑、自己接活、人不在也干。右边这两款产品都是这个思路，我们分开看它们各自怎么设计的。

先看 Meta 的 Muse：它在云端配了带浏览器、文件系统和终端的专属电脑；定好目标后能按定时或相关事件自己跟进，也会主动发消息找你；长任务在你关掉 App 后还会接着跑，由另一个独立代理把关出网，碰到发邮件、下单付款会停下来找你批准。

再看 OpenAI 的 Dots：每个 Dot 在云端自带一台电脑和浏览器，和你自己设备的登录态隔开；除了按指定时间或事件触发，它还能自己判断什么时候暂停、什么时候醒来接着干；就算你的设备关机了，它的云端任务照样跑，对外动作靠自动审查把关——写草稿不等于直接发送，改密码必须归你本人，需要时你也能随时接管它的浏览器。

再看 Grok Bot（官方页面现署名 SpaceXSI，2026 年 11 月刚发 1.0 正式版）。官网上虽然有标题写“每个 Bot 有自己的电脑”，但按官方技术文档的明确口径，云电脑是按用户账号配的：同一账号下的多个 Bot 共用一台云电脑、共享文件和登录态，每个 Bot 分一块独立屏幕同时干活，再由一个主 Bot 对接你、协调其他 Bot。

看第二、第三行：关掉 App、电脑或手机，后台任务和日常流程照样在云端跑。只要提前配好触发规则，除了定时，像 Slack 消息、GitHub 等系统事件、发给 Bot 的邮件或 webhook 都能叫醒它。

第四行是它的人机接管设计：普通账号密码走私密代填，直接填进网页，Bot 看不见明文；遇到单点登录（SSO）、passkey 或过不去的验证码，Bot 不会硬闯，而是把云电脑交出来让你接管操作，办完再把控制权还给它。

到了第四级台阶，谁说 AI 同事只能是一个？但光同时开几个 Agent 窗口，那只叫「一群 Agent」，还不算「一个组织」。

从「一群 Agent」变成「一个组织」，Harness 上多出的是屏幕底下这三样：总管调度、角色分工、并行执行。像刚才看的 Super Agent 原型用一个 Router 加多个 Worker，Grok Bot 用主 Bot 协调多块屏幕上的其他 Bot，就已经是小组织了。

再往前走一步，这是我个人的判断：未来的 AI 组织，甚至会由 AI 自己招人、自己定分工。
