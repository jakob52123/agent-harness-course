接下来是记忆，这是重点。Agent 的记忆我分成三层：

长期记忆，是 System Prompt：我是谁，遵循什么准则？

中期记忆，是项目文件：这个项目有什么规则和经验？

短期记忆，是这一次会话：这次做什么，已经做到哪儿？

不管哪一层，存下来的东西都要在开工的时候放进上下文，模型才看得见。

先看长期记忆，System Prompt 长什么样。这是我本机的 Pi 每次请求真正发给模型的系统提示词，我把它翻成了中文，一共五块：第一，身份，你是谁；第二，会用什么工具，你能做啥；第三，以什么方式去行动，你该咋做；第四，Pi 的说明书在哪，用户问到 Pi 本身才去读，这块有点像在打广告；第五，我自己配置的技能。

多长？Pi 的作者说过，出厂的系统提示词加上工具定义，一共不到 1000 个 token，差不多一页纸。我这份长一点，多出来的工具和技能是我自己装的。

再看 Claude Code。左边这个不是官方发布的，是 GitHub 上有人从 Claude Code 的安装包里拆出来的系统提示词，一共 810 段，用的时候按场景拼起来。一个一页纸，一个 810 段，又是极简和全家桶的对比。

Claude Code 还有一份长期规则，叫用户级 CLAUDE.md，对你电脑上所有项目都生效。这是我自己的那份：用中文跟我沟通，没有例外；能并行的都并行，省时间优先；对我的决策有疑问，一定要主动提出来。这些就是我希望它在所有项目里都遵守的准则。

压缩顺带提一句：对话太长了，Claude Code 会自动把前面的内容压成摘要，早先说过的要求可能就丢了。所以要它一直记住的规矩，不能只在对话里说，要写进 CLAUDE.md。我这份里专门写了一句「压缩之后接着干活，也要用中文」，就是防这个。

中期记忆，第一块：这个项目应该怎么做？AGENTS.md，项目的「工作手册」：使用什么语言，遵守什么规范，怎样运行和测试。至少要包含项目的语言规范、踩过的坑、最佳实践。

Claude Code 里这个文件叫 CLAUDE.md。

Claude Code 官方的建议是：同一个错误犯第二次，就写进这个文件。

开源项目也这么写。这是 Pi 自己仓库里的 AGENTS.md，同样三类。

语言规范：不准用 any，不准动态 import。这两条是写代码的规矩，大家不用懂，知道这是语言规范就行。

踩过的坑：同一个目录里，可能同时跑着好几个 Pi 会话。所以禁止 git add -A、git reset --hard 这类命令，它们会把别人的改动一起带走。还有，别直接跑全量测试：有接口密钥的时候，测试会真的去调收费的模型接口，花真钱。

最佳实践：改完代码跑一遍检查；没让提交，就别提交。

中期记忆的第二块：这个项目之前学到了什么？MEMORY.md 加相关的记忆文件，项目的「经验笔记」：用户纠正过什么，哪些决定已经确认，哪些背景下次还会用到。

工作手册是人写给 Agent 的；经验笔记是 Agent 自己边干边记的。拿 Claude Code 举例，它每个项目有一个记忆文件夹，这是做今天这份课件的 Claude Code 自己记的。

MEMORY.md 是目录，一条一行，每次开工都会读。比如这条：链接不要放二维码；这条：能自己做的别留给用户。这些都是我纠正过它的。

官方把记忆分四类：user，你是谁、什么偏好；feedback，纠正过什么、认可过什么；project，在做什么、定了什么；reference，资料在哪儿。

点开一条，一条一个文件。那天我说了一句「所有的链接不要放二维码，要给我能跳转的链接」，它就记下来了，还写了为什么、以后怎么用。之后每次开工它都看得到，不用我再说第二遍。

记录只追加、不删除
模型只看「摘要 + 最近的消息」，
原文还在
抖音 @Kieran的AI笔记 · Pi Agent 上下文压缩

短期记忆，就是这一次会话。Pi 把每次会话存成一个文件，每条消息一行；下次用 pi -c，就能接着上次继续。

会话太长了怎么办？就要压缩。

简单说两句树状压缩：Pi 的会话记录只追加、不删除，每一条都记着自己接在哪一条后面；而且可以跳回任意一步，从那儿另开一条往下聊，就分了叉，所以是一棵树。

快满的时候，把前面一大段交给模型写成摘要，挂到树上；模型下次只看「摘要 + 最近的消息」，原文还在，随时能回到压缩前。
