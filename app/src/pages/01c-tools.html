我们直接切入重点，先讲工具。这里是一个对比：Pi 是极简路线，简单在它默认只开 4 个工具，只能通过这 4 个工具的组合去实现不同的功能；与之相对的是 Claude Code，它有 50 多种工具，根据不同的场景去触发。

工具，就是 Agent 能做的具体动作。Pi 这 4 个是 read 读文件、write 写文件、edit 改文件、bash 跑命令；Claude Code 的官方工具表列了 50 多个。Pi 要搜文件，就用 bash 跑一条搜索命令；要上网，也是 bash。工具少，提示词就短，模型也不用挑。Claude Code 是每一类事给一个专门的工具：搜索有搜索的，网页有网页的，派子 Agent 有派子 Agent 的。专门的工具还有个好处：可以一个一个管权限，读文件不用问你，跑命令要先问你——这个后面讲。

那 LLM 到底是怎么用上这些工具的？

这就是 Function Calling。大家注意，LLM 自己是不能读文件、不能跑命令的，它只会输出文字。Function Calling 就是让它输出一段格式固定的调用请求：调哪个工具，传什么参数；真正动手的是 Harness。

大模型请求读取表格，工具是 read，参数是文件名。

Harness 执行读取，并返回文件内容。这就是一次完整的工具调用往返。

模型继续判断，提出调用，这次是用 bash 跑一段 Python 去算数，循环就继续下去了。

所以 Function Calling 讲的是「怎么调用工具」：LLM 提出调用，Harness 执行并返回结果。这个调用过程，被 Agent Loop 组织起来，持续推进任务。Agent Loop 我们后面串起来讲。

Tool Use 有四个重点概念：工具、Function Calling、Permission 和 Sandbox。前两个讲完了，接下来是 Permission，也就是安全边界和权限：哪些可以直接做，哪些需要特殊处理。

怎么限制？每次工具调用执行之前，Harness 先拿规则对一遍。

分三档：Allow 直接做，比如读文件、搜代码、改项目文件；Ask 先问人，比如删文件、装依赖、git push 推代码；Deny 不准做，比如读密钥、改系统目录。为什么要分级？因为动作的风险不一样：读错一个文件无所谓；删文件、推代码，做了就撤不回来；密钥、系统目录，碰都不该碰。

右边是 Claude Code 官方文档里的配置示例：npm 脚本和 git commit 直接放行，git push 一律拒绝。同一个动作放哪一档，是团队自己定的。

规则冲突了听谁的？Claude Code 是先看 deny，再看 ask，最后看 allow，先命中哪条就听哪条。所以 deny 里写了 git push，allow 里怎么写都推不出去。

但问多了也有问题：人会烦，最后闭眼点同意。Anthropic 管这个叫「审批疲劳」，反而更不安全。所以还要第四个概念：沙箱。

Sandbox

Claude Code
macOS · Seatbelt　 Linux · bubblewrap

Sandbox 沙箱，就是给模型一个独立的、隔离的运行环境。你可以理解成给 Agent 一个关上门的房间。

两道墙：文件，只能改工作文件夹里的东西；网络，只能连批准过的网站。注意它默认只拦「改」，不拦「读」，所以网络这道墙很关键：就算读到了密钥，也发不出去。

这两道墙是操作系统强制的，不靠提示词：Claude Code 在 Mac 上用系统自带的 Seatbelt，在 Linux 上用 bubblewrap。为什么不能靠提示词？你在提示词里写「禁止删文件」，模型可能不听，也可能被文件里藏的一句话带偏。沙箱是系统层面的墙，模型想越也越不过去。

Permission 和 Sandbox 是配合着用的：Permission 管「这一步能不能做」，Sandbox 管「做的时候能碰到哪」。房间里的事不用问你，要出房间才问你。Anthropic 说他们内部用了沙箱之后，确认弹窗少了 84%，大大缓解了上一页说的审批疲劳。
