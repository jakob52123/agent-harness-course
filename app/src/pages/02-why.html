先看有哪些 Harness。我们就拿刚刚第 02 章拆过的五样零件当尺子，按列对比屏幕上这四家：第一列 Loop，前三家都是底座自带循环，没有后续工具调用或任务做完就停；只有 DeepSeek Harness 把循环也做成了可替换的插件。

第二列工具，看各家内置了多少个：Pi 一共 8 个，默认只开读、写、改、跑命令这 4 个；Claude Code 官方工具表里有 50 多个；Codex 官方没出清单，按源码数约 30 个，读文件也靠跑命令；DeepSeek Harness 出厂的插件里有 60 多个工具，每个工具都是一个插件。

第三列上下文和记忆，AGENTS.md 和 CLAUDE.md 是人写给 AI 的项目规矩文档；在这之外，Claude Code 带自动记忆，Codex 带本地记忆。

第四列 Skills，四家做法几乎一样，都是用 SKILL.md 存操作手册，按需加载。

第五列权限和沙箱是最大的分水岭：Pi 默认不逐步弹窗、无内置沙箱；Claude Code 沙箱默认关，新版在支持 auto 模式的交互式终端和 VS Code 里默认派第二个分类器模型替你审批；Codex 默认用系统沙箱限制工作区并断网、越界才问；DeepSeek Harness 则把沙箱和审批也做成了插件，默认先问人。

先看「记忆」，两家都是「项目规矩文档 + 跨会话记忆」：Claude Code 读你写的 CLAUDE.md，并把你的纠正和偏好记进自动记忆；Codex 读 AGENTS.md，再配一套存在本机的本地记忆。

再看「护栏」，两家思路正好相反：Claude Code 沙箱默认关，新版在支持 auto 模式的交互式终端和 VS Code 里默认派第二个分类器模型替你审批；Codex 默认断网，用系统沙箱管能碰的范围（通常是当前工作区），再配审批策略管什么时候必须停下来问你（比如越界时才问）。

顺带提一句工具颗粒度：Claude Code 拆出了专门的读文件、改文件等细分工具，而 Codex 更依赖命令行，主要靠 exec_command 跑命令和 apply_patch 打补丁。

DeepSeek Harness

Everything is a plugin
  • Loop
  • 工具
  • 权限
  • Skills
  • 压缩
  • MCP

前面的 Pi、Claude Code 和 Codex 都支持扩展，而 DeepSeek Harness 的口号叫「Everything is a plugin（一切皆插件）」。它不光外围的工具、Skills、上下文压缩和 MCP 是插件，连最核心的 Loop 和权限（沙箱与审批）也都做成了插件，能通过配置按需替换。

目前它还处在开发者预览阶段（屏幕上这个 0.2.2-rc.3 是预发布版）。看完了这四家 Harness 底座，接下来我们就看用这些底座搭出来的 Agent 产品——像后面马上要看的 DeepSeek Super Agent 研究原型，就是以它为底座，直接往上多挂了一个插件包搭出来的。
